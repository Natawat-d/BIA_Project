AT82.04 · Business Intelligence & Analytics

System Architecture — Speaker Script

Netflix Customer Retention Intelligence DSS · walk the diagram top-to-bottom
Target: ~5 minutes total · ~1 minute per section · bold = say with emphasis

01Overview — what we built

~45 sec

Our system is a Decision Support System built as a single, reproducible pipeline: ETL → Data Preparation → Model → Dashboard. It maps directly to Simon's framework — Intelligence (understand churn), Design (predict who will churn), and Choice (prioritise and simulate retention).

The whole stack is containerised with Docker and deployed on AWS EC2, so anyone can reproduce the exact run — the pipeline is deterministic (fixed random seed) and runs end-to-end on a single command.

Point to: the outer AWS EC2 box and the big Docker field wrapping everything.

02Data Layer — ingest, clean, warehouse

~60 sec

We start from the raw dataset — 5,000 subscriber records, 14 columns. The ETL stage, written in pandas, does three things: Extract reads the CSV; Transform cleans it — fixing data types, removing duplicates, imputing missing values, validating ranges, and normalising the churn label to 0 or 1; and Load writes the results out.

Load has two destinations. First, a clean CSV that the rest of the pipeline uses. Second — and this is our BI core — it loads a fact table plus KPI views into PostgreSQL, which serves as our data warehouse using a star schema. If the database is offline, the system falls back to the CSV, so it always runs.

Point to: Raw dataset → Pipeline (ETL) → Data Warehouse (PostgreSQL).

03Analytics Layer — prepare, train, score

~70 sec

Data Preparation turns the clean table into model features — 15 features (including three we engineered: watch-per-profile, engagement segment, and recency bucket) which one-hot encode to about 35 inputs. All preprocessing lives inside a scikit-learn Pipeline, fit on training data only, so there's no leakage.

We train four models — Logistic Regression, Decision Tree, Random Forest, and XGBoost — and automatically select the best by cross-validated PR-AUC, then calibrate it with Platt scaling (a smooth sigmoid fit) so the probabilities are trustworthy and never exactly 0% or 100%. The Scoring step outputs, for every customer, a churn probability, a risk tier, the revenue at risk, and a recommended action.

Point to: the Pipeline container — ETL → Prep → Training → Scoring — and the model.pkl in the volume.

04Presentation Layer — the dashboard

~55 sec

The front end is an interactive Streamlit dashboard with charts built in Plotly. It reads the processed outputs directly — clean.csv and the scored customers — and can also query the data warehouse.

The pages mirror Simon's framework: Home and Descriptive Analytics are the Intelligence phase — KPIs, churn patterns, and a "where to focus" priority view; Churn Risk is the Design phase; and Retention Simulation is the Choice phase — a what-if campaign simulator. Every view is filterable in real time by region, plan, engagement, and risk.

Point to: the Dashboard container (Streamlit + Plotly) and its four pages.

05Infrastructure & Deployment

~40 sec

Everything runs under Docker Compose as three services — the PostgreSQL warehouse, the pipeline (which runs ETL, train, and score), and the dashboard. One command brings the whole stack up, and because the seed is fixed, the results are reproducible every time.

We deployed it live on an AWS EC2 instance in the Bangkok region, so the dashboard is reachable in a browser over HTTP — it's not just a local demo, it's a live, hosted application.

Point to: the Docker boundary inside AWS EC2, and the HTTP arrow out to the users.
If asked "is it real?": The dataset is synthetic and roughly 50/50 balanced, so we present this as a methodology demonstration. XGBoost's near-perfect score is a leakage red flag we flag ourselves — we treat Random Forest as the credible best model pending a full feature audit. Saying this reads as rigor, not weakness.
